# Internationalization (i18n) & Multi-Language Guide

This document outlines the internationalization architecture of AudioBlocks and provides a step-by-step guide for developers on how to add support for new languages.

---

## Overview

AudioBlocks uses a lightweight, React Context-based internationalization system (`I18nContext`) located in `app/src/context/I18nContext.tsx`.

### Core Components

1. **`I18nContext` (`app/src/context/I18nContext.tsx`)**:
   - Manages the active locale state (`en`, `es`, etc.).
   - Persists user language preference in `localStorage` under key `audioblocks_locale`.
   - Exposes `useI18n()` hook returning `{ locale, t, setLocale, availableLocales }`.

2. **Translation Dictionaries (`app/src/locales/`)**:
   - `en.ts`: English translation dictionary; serves as the base source of truth and TypeScript type definition (`Translations`).
   - `es.ts`: Spanish translation dictionary typed against `Translations`.

3. **`LanguageSwitcher` (`app/src/components/LanguageSwitcher.tsx`)**:
   - Dropdown UI component that allows users to switch between supported languages dynamically.
   - Automatically populates dropdown options based on `availableLocales` and `t.language`.

---

### Step 2: Add Language Label to Existing Locales

Update `language` block in `app/src/locales/en.ts` (and all other existing locale files, e.g. `es.ts`) so that the name of the new language is available across all translations:

```typescript
// In app/src/locales/en.ts
language: {
  label: "Language",
  en: "English",
  es: "Español",
  fr: "Français", // Add label for new locale
},
```

### Step 3: Register Locale in `I18nContext.tsx`

Open `app/src/context/I18nContext.tsx` and register the new locale:

1. Update the `Locale` union type:
```typescript
export type Locale = "en" | "es" | "fr";
```

2. Import the new locale dictionary:
```typescript
import fr from "@/locales/fr";
```

3. Add the locale to the `locales` map:
```typescript
const locales: Record<Locale, Translations> = { en, es, fr };
```

### Step 4: Verify & Test

1. **Type Checking**: Run TypeScript compiler check from `app/` directory:
   ```bash
   npx tsc --noEmit
   ```
   If any key is missing or misspelled in your new translation file, TypeScript will report an error.

2. **Linting**: Ensure code adheres to repository style standards:
   ```bash
   npm run lint
   ```

3. **Runtime & UI Test**:
   - Start the dev server (`npm run dev`).
   - Use the `LanguageSwitcher` dropdown component in the top header or settings to select your newly added language.
   - Confirm that UI text updates and that your selection persists across page refreshes.

---

## Usage in Components

To use localized strings in client components:

```tsx
"use client";

import { useI18n } from "@/context/I18nContext";

export function WelcomeMessage() {
  const { t, locale, setLocale } = useI18n();

  return (
    <div>
      <h1>{t.header.welcome}</h1>
      <p>{t.status.loading}</p>
    </div>
  );
}
```
